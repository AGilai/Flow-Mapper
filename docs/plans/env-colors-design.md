# Environment colours and cross-env flow tabs

Design, not built. Builds on `docs/plans/tabs-active-cap-design.md` (active tab = 3px full bar + joined fill, "Tab" button, plain click replaces, 10-tab cap). Files read: `flow-tabs*.js`, `flow-tab-view.js`, `flow-tab-data.js`, `flows.js`, `state.js`, `env-picker.js`, `env-settings.js`, `store/envs.ts`, `store/colors.ts`, `core/users-match.ts`, `tokens.css`, migrations 005/008/016. Not verified in a browser. Colour values below are starting points: the coder runs a contrast check (3:1 bar on `--paper`/`--surface`, 4.5:1 chip text) and adjusts.

## 0. Findings that change the brief
- `envs.colors` (migration 008) is NOT an env colour. It is the **component** slot map `{component: 1..8}` behind `--cmp-1..8` (UI-GUIDE section 8). Do not reuse it. Add a new column.
- The tab's top bar today is the **transport** colour (`--tc`, set per tab in `flow-tabs.js`). Env colour takes the bar, so the transport hue moves to the tab's leading glyph (the `ENTER` / `FULL` svg stroke and `.tn` text), where it still tells http from queue.
- `--cmp-*` (components) and `--t-*` (transports) already exist. The env palette must read as chrome, not data: it only ever appears on tab frames, chips and the env picker, never inside a diagram.

## 1. Env colour model
- **Palette**: 10 slots `--env-1..10`, each with `--env-N` (bar, border, swatch) and `--env-N-ink` (chip text), light and dark in `tokens.css` (both dark blocks, like `--t-*`). Names (shown in settings and as `title`): 1 Teal, 2 Orange, 3 Violet, 4 Rose, 5 Green, 6 Brown, 7 Steel, 8 Plum, 9 Pine, 10 Navy. No red (problem), no yellow (status marks `--new`), nothing near `--accent`.
  Light bar / ink: teal `#0f8b8d/#0b5f61`, orange `#d9650b/#8a3f05`, violet `#7c4dd6/#55329a`, rose `#d6336c/#9a1f4b`, green `#3d9a3d/#25661f`, brown `#9a6b3a/#6b4520`, steel `#5b7a99/#3b5670`, plum `#8e3a8e/#632763`, pine `#1f6f50/#14472f`, navy `#3346a8/#222f78`.
  Dark bar (ink = same hue mixed 60% with `--ink`): `#3cc4c6 #ff9a4d #b093ff #ff7aa8 #7bd07b #d4a373 #9bb7d4 #d98ad9 #4fc79a #7f93ff`.
- **Storage**: migration `018_env_color.sql`: `ALTER TABLE envs ADD COLUMN color INTEGER` (NULL = automatic) plus a backfill that stores the slot for every existing row: `(count of envs ordered before it by created_at, name) % 10 + 1`. So existing envs keep one colour for good (prod gets 1). The `colors` column is untouched.
- **New envs**: the create path (`env-copy.ts`, blank and copy) picks the lowest free slot among stored slots; only when all 10 are taken it repeats the least-used. A copy never inherits its source colour (the point is to tell them apart). Envs with no `envs` row (snapshots only, the rollout safety net) get the rank fallback at read time.
- **Pure core**: `core/env-colors.ts`: `ENV_COLORS` (names), `nextFreeSlot(taken)`, `envSlot(meta, name)` (stored, else rank fallback). Shared with the browser and the preview build, so the preview shows the same colours.
- **Override**: Environment settings (`#/envs/<name>/settings`, `views/env-settings.js`, also the picker's "Environment settings" link) gets a "Colour" section: a `radiogroup` of 10 swatches, each with its name, plus "Automatic". Allowed on sealed and design envs (an annotation like level names, saves on change, no draft). Picking a colour used by another env is allowed; the swatch shows a small "also <env>" hint. 
- **API**: `EnvMeta.color: number` (always resolved 1..10) and `colorAuto: boolean` in `GET /api/envs/meta` and `GET /api/envs/:env`; `PUT /api/envs/:env/color {color: 1..10 | null}` (events: `env.updated`, so open UIs refresh meta). MCP: `list_envs`/env info return `color` and its name; one write tool `set_env_color`. `docs/API.md` and the OpenAPI/contract test get the field.
- **Preview**: `envMeta` is bundled with the computed colour; setting it is refused like creating an env (settings show the swatches disabled with the usual preview note).

## 2. Where colour shows (restrained)
- **Flow tabs** (the main use): bar and border carry `--ec: var(--env-N)`. Active: full 3px bar + joined fill (tabs-active-cap). Inactive: bar at 45% (`color-mix`), label weight 500. The active state never depends on hue: fill, height, no bottom line and weight stay as in that design. Tab `.x`, hover and focus styles unchanged. The popover `.tabrow` left border uses `--ec` too.
- **Env chip in each tab** (non-colour cue, colour-blind and similar hues): a 10px caps chip with the env name truncated to 6 characters (`prod`, `design`, `staging`->`stagin`+ellipsis, full name in `title`), `background: color-mix(--ec 16%, --surface)`, text `--env-N-ink`. Shown only while open tabs span 2+ envs (a single-env tab strip stays as it is today, no noise); the bar colour shows always. Two envs whose first 6 characters collide get a numeric suffix (`stag·1`, `stag·2`) by a pure `chipLabels(envs)`.
- **Env picker**: each option gets a 8px round swatch before the name (`.env-opt`), the trigger (`.env-cur`) too. The rail trigger gets a 3px left border in the colour. Text is unchanged, so it reads without colour.
- **Flows list header** (`pageHead` sub line `N entry points in <env>`): a chip with the same swatch + env name replaces the plain env word. This says which env the list (and plain click) belongs to when tabs of other envs are open.
- **Maximize bar** (`.max-bar`): the active tab's env chip (always, even single env) and a 3px top border in `--ec`, since the tab strip is hidden there.
- **Sub-flow Back trail** (`.crumbs`): no colour; a sub-flow opens in its parent's env so the bar already says it. Only when the origin tab is in another env than the current (never happens: sub and parent share env) skip.
- Not coloured: the diagram, the list rows, the rail apart from the picker, the design strip (it keeps `design` chip text).

## 3. Cross-env tabs
**Key format.** A tab key gains an optional env prefix: `<esc(env)>|<key>` (`prod|checkout/post-order`, `design-x|fn:api/save`). `esc` gets `|` added so a service name cannot fake a prefix. Unprefixed = the env of the URL (`env=`), so every old link works unchanged. The URL writer omits the prefix for tabs of the current env (short links stay as today) and writes it for all others. Origin inside `@origin` stays unprefixed (same env as its sub tab). `parseKey` returns `env: string|null`; state keys are held **fully qualified** internally (`env|key`) so switching env never changes what a tab is: on `setEnv` nothing is closed, the current env param just changes, and `persist()` re-derives which keys need a prefix. On load, `decodeUrl` qualifies unprefixed keys with `env=`; an unknown env prefix gives a tab in an error state ("Environment <x> not found", close button works), not a dropped tab.

**What reads `state.env` and must become per tab** (host passes `env` per tab; today `host.env` is one value):
- `flows.js`: one `createTabData(state.env)`, `createDescStore(state.env)`, `nameOf` (flow names), `loadMarks()`, `subs`/subsystems, `host.env`. Become a small `envCtx(env)` cache (`flow-env-ctx.js`): lazy per env, builds `{ data (trace/endpoint), desc, names, marks, subs, meta }`; the list keeps using the current env's.
- `flow-tab-view.js`: `host.env` -> the tab's env for `openGenerate`, `createItemStore` (action items), `createComments`, `createInside`, `messagePanel`, "no behaviour in <env>" text, and `host.openEntry` (opening an entry from inside a tab: same env as the tab, not the current).
- `api.js` `withDraft`: adds `draft=` to every GET under the env. A tab of another env must not send the current draft (draft slugs belong to one env). See drafts below.
- Component colours: `cmpVar` / `slotOf` read `state.env`; they take the tab's env (`slotOf(meta, env, ...)` already can; `cmpVar` gets an env arg, flow-render passes it).
- Caches keyed by env only partly: `marks-store`, `subsystems-store`, `graph` caches. Check each key includes env; where it keeps one "open env" (marks, subsystems) the tab asks through the `envCtx`.

**Flows list and clicks.** The list is always the current env's (`env=`). Plain click = `replaceActive(S, 'cur|key')`; "Tab" = `openTab`. Choosing another env in the picker changes the list and the env param only; open tabs stay and the active tab stays active. The `has-tab` dot and `aria-current` compare the fully qualified key, so a prod tab never marks the same-named design row. Clicking a row whose flow is open in this env switches to it.

**Switching env while a tab of another env is active.** Page content (the tab) and list differ in env on purpose; the page head says "Flows" and the list chip says the list's env. The design strip (`design-strip.js`, draft bar, Edit) follows the **list/current env**, not the tab. A tab of another env is therefore read only: no pencils (`pencils(host)` gets `host.readOnly`), no edit forms, comment and action-item input stay allowed (they are annotations, per `guardEnv`), and a one-line note in the tab head: `Viewing <env>. Switch to it to edit.` with a button that does `setEnv`.

**Drafts.** A design env's draft slug belongs to the current env only (`draft=`, `designKeys` cleared by `setEnv`). Tabs of the current design env follow the active draft as today. A tab of another design env reads its committed state with marks against the source (`compare=source` rules) and shows `no draft` in its read-only note. Consequence: "prod flow next to its design-draft flow" works when the design env is the current one (draft shown) and prod is the foreign tab. The reverse (current = prod, design tab foreign) shows the design without its draft. If that is not enough, step 3 later: tab key suffix `#draft` to pin a slug per tab (out of scope now, listed as a risk).

**Cap and sub-flows.** The 10-tab cap counts all tabs across envs; the toast text is unchanged. Sub-flows and full-flow tabs inherit the parent's env (the key is built with the parent's env; the crumb link reopens the origin in that env). "Open all distinct" and Alt+Shift+T work on qualified keys (the closed stack stores them).

**Env closed, renamed, deleted.**
- Delete (`env-delete.js`, `envDeleted` event): tabs of that env turn into the error state above (not silently closed), with "Close" and, in the delete dialog, a line `N open tab(s) of this env will show as unavailable`. Reload drops them with the toast `Closed 2 tabs of deleted environment <x>`. Rename is not a feature today; if added, `persist()` rewrites keys from the event.
- Env list is loaded once (`state.envs`/`envMeta`); a tab of a missing env checks `state.envs` before fetching so there is no request storm.

## 4. Risks and split
- Biggest risk: hidden `state.env` readers (the list above is from reading; the coder greps `state.env` and `host.env` under `web/js/views`, `design/`, `components/`, `pane/` and checks each). A wrong env means data from the wrong env under the right colour, so tests below force this.
- Draft model for foreign tabs (read only, no draft) may disappoint; flagged, small fix later.
- Tab width: chip + transport glyph + `.tn` + title; the chip only appears with 2+ envs and title truncates first.
- Colour collision with `--cmp-*` hues: mitigated by use only on chrome and by the chip; review in dark mode.
- `|` in `esc` changes keys that contain `|` in names (old links decode the same through `%7C` only for new keys; an old key with a raw `|` in a service name would read as an env prefix). Negligible; the parser checks that the part before `|` is an env in `state.envs`, else treats the whole as a key.

**Step 1 (0.34.x, small, safe): env colours, tab frame, picker.** Migration 018, core, API/MCP, settings section, tokens, `--ec` on tabs (transport hue to the glyph), picker swatches, list-header chip, maximize chip. All tabs are still of one env, so tabs carry the current env's colour; the chip is hidden. Ships useful alone (the user sees what colour each env is, and tabs get framed).

**Step 2 (0.35.x): cross-env tabs.** Key format and URL, `envCtx`, per-tab env in tab view, read-only foreign tabs, picker no longer clears tabs, chips appear, delete/unavailable state, cap across envs.
