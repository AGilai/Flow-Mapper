Design environments: an HLD for the SASE project

Revision 4: frames 1–9 approved and built (0.24); frame 10 adds references (🔒), importing one level into a design, and partial-flow warnings. Static mockup for the maintainer. A design environment is a normal Flow-Mapper environment that holds a high-level design. You start it from any environment (prod, or another design), edit it on the canvas through shared drafts, sketch at subsystem level and refine down to components and endpoints, pull in what's missing from other environments while you work, and discuss any item. Names are illustrative. Tokens, chips, toolbar, tabs and the docked panel are the app's own (0.19.1).

  1. Status is computed, not stored. Every environment keeps the revision it was copied from (its baseline). The server compares the current state with the baseline at read time and marks each item New, Changed, Removed, or nothing (unchanged, "From prod" in the meta line).
  2. On every level. Subsystem link, component, endpoint, call, queue, message, a field of a message, a field of a collection. The mark goes on the highest new item only: a new component's endpoints are new by implication and don't repeat the icon, so the page doesn't fill with stars.
  3. The new icon is a small yellow spark, with one short twinkle when the page loads (off with reduced motion). It's the only yellow in the app: --warn stays amber and is never shown as a star.
  4. Words. Environment › subsystem › domain (later) › component › endpoint / message › field. A flow has a name ("Agent connects to POP"); the entry key is secondary. A draft is a named, shared set of changes that is applied in one step.
  5. Harvested environments stay read-only. Edit mode, drafts and import exist only in design environments.
--new (spark)--new-ink (outline, text)--warn (unchanged, amber)

Frame 3. Subsystem level: rolled-up calls and abstract links

#/?env=sase-hld&level=subsystems. The same design, one level up. Calls between components roll up into one line per direction and transport. Two links were drawn at this level and have no component yet; one is being refined.

  1. Roll-up is automatic and goes both ways. Every call between components in two subsystems shows here as one line per transport, labelled with the count ("2 calls · http"); thickness grows with the count. Click it to list the calls. Nothing is stored for a roll-up.
  2. An abstract link is a real item, drawn at subsystem level: a name, a direction, sync or async, a description. Its ends are open circles on the box edge: "no component here yet". It can be discussed, and it can be marked New like anything else.
  3. Refine end by end. The panel picks a component for each end, then an endpoint (or a new one). An end that has a component draws into that component's row; when both ends have endpoints, the link becomes an ordinary call at component level and rolls up here like the others.
  4. The assistant suggests ends from the design ("pop-telemetry already sends flow logs to telemetry-ingest over amqp"), so refining usually starts from what's already drawn.
  5. Inside each box, the components are a list with their marks, prod ones muted. Click a name to go down to it at component level.

Frame 4. Editing a flow in a draft

#/flows?env=sase-hld&draft=use-token-grant&tabs=sase-agent/tunnel.open. The flow "Agent connects to POP" in Edit mode, inside the draft that came from the discussion in rev 1: replace the new POST /token/exchange with prod's POST /token.

  1. View · Edit is a toggle on every page of a design environment. Edit opens a draft (a new one, or one picked from a list); nothing you change touches the environment until Apply.
  2. The draft bar names the draft, counts its changes (+1 −2 ~1), says who has worked on it and how many discussions it has, and holds Review changes · Discard · Apply. Anyone can open the same draft; there is no ownership yet (see the spec: a later invite model fits on top).
  3. Draft changes are drawn in place: what the draft removes is faded and struck through with "removed in draft"; what it adds carries an "in draft" chip. Review changes lists the same set as text.
  4. Full create, edit and delete on the canvas. "+" in a band adds a component to that subsystem. Dragging the "+" under a bar to another lifeline adds a call. Clicking an arrow or head opens its form in the panel. Delete is in the form, not on hover.
  5. Discussions on anything: the bubble with a count sits on what it's about: the flow (on the tab), a component (on its head), a call (on its arrow). The rev 1 thread now lives under this draft's change.
  6. The spark marks the highest new thing: heads of new components, and the new endpoint on a prod component. The calls of a new component don't repeat it.

Frame 6. Importing what's missing while you work

Even a design that started Blank can pull in components and endpoints from other environments when it needs them. Three ways in: the assistant notices while drafting, a call points at something this environment lacks, or you search.

  1. The assistant checks as it drafts and asks once, with a short list: what matches, what exists elsewhere (import?), what exists nowhere (add as new). It never imports without asking.
  2. A call to something missing shows a neutral notice (not a problem: in a design it's normal) with "Import from prod" when another environment has it.
  3. Import from another environment searches every environment, groups results by environment, and says what comes along. Imports go into the open draft, so they're reviewed and applied like any edit. Their baseline is the source's current revision.
  4. Imported, not new. An imported endpoint is unchanged against its own source, so it gets no spark. The meta line says where it came from ("from prod, imported Oct 22").

Frame 9. Every flow: description, step walk and squeeze

Applies to every flow page, harvested or design. "Agent connects to POP" after the draft was applied, in a viewport too narrow for all six lifelines. Try ‹ and ›: the highlighted step, its description and the fold move together.

  1. The flow description sits under the flow's title, full width, as a real text box (click to edit, Human and AI versions as in 0.14.0, with the AI one marked outdated when the flow changes). It's collapsible; the choice is remembered per viewer. It leaves the panel, which only describes what's selected.
  2. Steps are numbered in the order they run: a tile at the start of each arrow. Returns aren't steps. A step inside a folded lifeline keeps its number on the fold.
  3. The step walk sits above the diagram: ‹ Step 3 of 7 ›, then the step's label and ends, then its description in a wide collapsible box. ‹ and › (and the ← → keys while the diagram has focus) move the highlight; the highlighted arrow gets the halo and its tile turns solid. Clicking an arrow jumps the walk to it.
  4. Squeeze (on by default) keeps the highlighted step's two lifelines and the caller on screen. Lifelines between them that the step doesn't touch fold into one narrow "⋯ 3" column; arrows into a folded lifeline stop at the fold with dots and keep their label and target name. Walking to a step recomputes the fold. Click the fold to open it; turning Squeeze off gives today's horizontal scroll.

Frame 10. References, importing one level, and partial flows

#/flows?env=sase-hld&draft=hld-import&tabs=sase-agent/in.tunnel.open&step=3. The agent's flow reaches two prod components whose behaviour isn't in the design: users-svc and activitylog. The user is about to import users-svc's posture endpoint so it can be changed.

  1. A reference has a lock. A copied endpoint without its behaviour (handler and call tree not in the design) shows 🔒 on its bar end, on its head and in lists, with the words "reference from prod". It's neutral, not a warning: referencing prod is normal in a design. A component with at least one reference endpoint shows the lock on its head; the panel says which endpoints.
  2. "Import into design" sits next to every lock: at the flow boundary, on the service page row, in the step panel. It never fires directly: it opens the preview on the right.
  3. One level, never recursive. The preview lists what comes along: the endpoint's handler and its call tree inside that component, the calls it makes, the stores it touches, the queues and DTOs it uses. What it calls in other components stays a reference (locked) and is listed under "Stays a reference", each with its own Import, so the next level is always an explicit choice.
  4. Imported is not new. Imported items take the source's current revision as their baseline, so they show no spark; the lock goes and the meta line says "imported from prod, Oct 21". Editing them later marks them Changed.
  5. A partial flow says so. When any step of a flow continues into a reference, a neutral line under the step walk says "Partial flow: 2 steps continue into references", with the names and Import links. The flow list shows a small lock next to such flows.
  6. Editing across a reference warns once. Opening the edit form of a call whose other side is a reference shows a callout in the form: the edit changes the call only, not what happens in the reference. Two buttons: "Import users-svc's flow first" and "Edit the call only". The choice isn't remembered: every such edit asks.

Phases

  1. Environments and marks: envs table, copy from any source (Blank, Components, Full), subsystems, kind client, baseline and the computed New / Changed / Removed down to fields, frames 1, 2, 5, 7.
  2. Drafts and editing: drafts with apply and discard, panel forms, then direct editing on the diagram, flow names, import (frames 4, 6).
  3. Subsystem level: abstract links, refine, roll-up, the level control (frame 3).
  4. Discussions: threads on any anchor, the assistant's replies, the all-discussions page, per-call AI descriptions (frames 4, 8).

Decided (rev 2)

  1. Copy from any environment, Full copy included in phase 1; the label is "From <source>".
  2. New is a small yellow spark, computed by the server by comparing with the baseline, on every level down to a field.
  3. Neighbours one hop.
  4. Discuss anything, plus an all-discussions view later; flows get names.
  5. Full editing through shared named drafts; sharing and invites stay naive (free-text author) with room for members later.
  6. Subsystem-level abstraction with refine and roll-up.
  7. Import on demand from any environment, by the assistant or by hand.
  8. References and import (rev 4, frame 10): a copied endpoint without its behaviour is a 🔒 reference; "Import into design" copies one level (its own flow and what it uses), never recursively; continuations stay locked and partial flows and edits across a reference say so.
  9. Every flow page (rev 3): a wide collapsible flow description under the title, numbered steps with a ‹ › walk and a wide step description above the diagram, Squeeze on by default.

Still open

  1. The changed mark: a yellow ring (shown) or a pencil glyph.
  2. Apply conflicts: when an item in the draft changed in the environment after the draft was opened, list it and stop (shown in the spec), or let the newer edit win.
