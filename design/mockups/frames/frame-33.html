Frame 33. Arrow notation: sync, async, return

Maintainer: "present an async line different than sync, and are we requiring to know which call a return belongs to, so maybe add 4-ret". The head shape carries sync vs async, the dash carries return, a back-reference bubble says which call a return answers. Transport colours and the RPC ⇄ glyph are unchanged. Data is invented.

  1. Three arrow kinds, three signals (33a). Sync: solid line, filled triangle head (as today). Async: solid line, open stick head, never dashed. Return: dashed line, open head. Line style says "is this a call or an answer", head says "does the caller wait". Today a fire-and-forget async is dashed with a filled head and reads as a return, and an async that opens a bar is drawn exactly like sync; both are fixed.
  2. Async marker in the number bubble (33a, 33b). The call bubble gets a small bolt after the number (3⚡, drawn as a path, not an emoji). It stays legible at 80% zoom (33b) and it is the only extra mark on a call; the open head is the primary cue, the bolt confirms it where heads are small. No "async" word on the canvas; the hover title and the legend spell it out.
  3. Returns name their call (33a, 33b). A return carries a muted outlined bubble ↩4 in the same position as a call's number, so the reader can tell which call it closes without tracing the bar. Calls keep the filled coloured bubble; returns are outlined and grey text, so numbered calls stay the visual skeleton. The return takes the colour of the call it answers.
  4. When the return label is dropped. The literal word "return" is never shown (today it is). A return value is shown after the bubble only when it carries information: a status or payload name that differs from "ok" (201, rows, id). Empty or ack returns are ↩4 alone. In 33b most returns are bubble-only and the diagram is quieter than today's.
  5. Async never gets a return; callbacks are calls (33a). A fire-and-forget (to a queue, no bar) ends at the lifeline with today's stop bar and has no ↩. When the callee later calls back (CR #147: web-app calls export-mgr async, export-mgr calls web-app sync twice), those are ordinary sync calls with their own numbers and their own ↩ returns; the async call is not "answered". Legend (33c) goes into the caption bar after Read / Write.
