Frame 13. Comments under each flow (new)

Maintainer: "comments capability per user under each flow - each comment is a rich text edit box - with a ui control for styling text bold/strike through/tables/colors". Comments are a list: anyone can post as many comments under a flow as they like (Asaf has two separate ones below); the composer always adds a new comment at the end.

  1. A "Comments (4)" section under the flow description, a collapsible box like the description (open state remembered per viewer). The count includes replies. It sits above the step walk, so the discussion is read before the diagram.
  2. A thread in date order, oldest first, so the composer at the bottom continues it. Each comment: avatar with initials, name, relative time (full date in the tooltip), "edited" in italics when it was.
  3. A step pill ("step 3", link colour) on a comment that is attached to a step; click it and the walk jumps to that step. Steps are the walk's numbers; if a flow changes and the step is gone, the pill reads "step 3 (gone)" and is plain text.
  4. Replies one level deep, indented with a rule. A reply has no Reply button of its own; replying to a reply attaches to the same parent.
  5. Your own comments show Edit and Delete (a small "you" tag by the name). Delete asks first. There are no accounts: "yours" means the name remembered on this browser matches the author, the same naive rule as drafts.
  6. The composer is a rich-text box. Toolbar: Bold, Italic, Strikethrough, text colour (7 swatches: default plus six palette colours), bulleted list, numbered list, link, table (inserts 3×3; with the caret inside a table a "Table" group appears: + row, − row, + col, − col). "Attach to step 3" is a toggle shown when a step is selected (on by default then). "Comment as" asks for a name once; after that a "Commenting as Asaf G. · change" line replaces it. Post and Cancel; Ctrl/Cmd+Enter posts, Esc cancels.

Storage, safety and reach

  • Stored as a sanitized HTML subset: p br strong em s ul ol li a table thead tbody tr th td span, with only href (http, https, mailto) on links and a class from the palette on spans. The server strips everything else, so what is shown is what was stored, and the client trusts nothing.
  • Colours are palette tokens, not hex: a coloured span stores class="cc-coral", and the class maps to the component palette tones (--cmp-*, contrast at least 4.4:1 on the surface in light, 7.4:1 in dark). A comment written in one theme stays readable in the other.
  • Paste keeps only the supported formatting: pasted HTML runs through the same filter in the browser, so bold, lists, links and tables from Word or a web page come across and fonts, sizes, backgrounds and hex colours are dropped.
  • MCP: list_comments (by env and flow, with since for polling) and add_comment (author, body as the same HTML subset or plain text, optional step and parent), so an assistant can read the discussion and answer in it.
  • Every environment has comments, harvested and design. A full copy of an environment copies its comments; Blank and Components copies do not.
