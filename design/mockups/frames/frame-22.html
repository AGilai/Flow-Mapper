Frame 22. Show broken flows (change request #85; maintainer approved the feature, the lead approves the visual)

A flow whose harvester could not resolve some calls used to fold them into “frontier: N steps” and look complete. This frame shows the five asks: an amber incomplete · N blocked badge (22a, 22b), a frontier marker that counts and expands its blocked steps (22b, 22c), a Why incomplete section in the info pane (22c, 22d), an Incomplete flows only filter (22a), and a reserved dashed style for LLM-inferred hops (22e). Dark mode is 22f, the amber tokens and their contrast ratios 22g. Sample: safer-auth POST /api/v1/api-internal/authenticate; build spec: docs/plans/incomplete-flows.md.

  1. Amber means “not fully mapped”, nothing else. It is a new, separate token pair (--inc for strokes, --inc-ink for text) because the app's --warn is 3.4:1 on white and fails for small text. Red (--t-broken) stays reserved for a link known to be broken.
  2. Never colour alone. The badge has a triangle icon and words; a blocked step has a “!” bubble, the word “blocked:” and a dashed stub that ends in a stop bar.
  3. One number, one rule. N counts gap=true unresolved steps the trace visits, across all services, folded frontier included; with no gap data it falls back to the entry's details.coverage.blocked. The Flows list can only know its own service, so its number may be lower than the trace's; the tooltip says so.
  4. The frontier marker is a button: border, chevron, hover and a keyboard focus ring. It is quiet (grey) unless it hides blocked steps, then its border and “· N blocked” turn amber.
  5. Complete flows are untouched: no badge, no “Why incomplete”, the marker reads “frontier: N steps”.

22c. Expanded: blocked steps marked, and “Why incomplete” in the info pane

Click (or Enter) on the marker: the folded steps are drawn under it. Ordinary frontier steps are grey dots as today; each blocked step has an amber row, a “!” bubble in the gutter and a dashed amber stub that stops at a bar, reading blocked: receiver type unknown over the call text. 22e. Reserved: an LLM-inferred step or edge

Nothing draws this yet; the style is fixed now so it is never confused with a code-proven hop. An inferred edge is dash-dot (long dash, gap, dot, gap) in its transport colour, with a small dashed-outline tag inferred (LLM) on the label. It differs from the existing return arrow (grey, even dashes, arrowhead pointing back) in rhythm, colour and the tag, and from the amber blocked stub (short dots, stop bar). An inferred step (a bar or dot) gets the same tag and a dashed outline. Never used for code-proven data, never amber.

22g. Amber tokens and contrast

Text uses --inc-ink (4.5:1 minimum, WCAG AA); lines, borders and stripes use --inc (3:1 minimum, non-text). Both are defined for light, dark by preference, dark by the theme switch and the forced-dark mockup wrapper. The existing --warn is not reused for text: it is 3.4:1 on white, which is why the last row fails. Fills are --inc mixed into the surface, never a separate colour.

For the lead to confirm (recommendations are in the build spec)

  1. List count vs trace count. Drawn: the list uses details.coverage.blocked (own service), the trace counts across services, so a row may say 3 and the trace 4. Recommendation: accept; the list tooltip says “in this service”.
  2. Filter shown only where coverage data exists. Recommendation: yes; disabled-with-(0) would invite “is it broken?”.
  3. Frontier expansion with blocked steps. Drawn: expanding shows the frontier steps with blocked ones marked. The cap is the existing frontier expansion limit; blocked steps are never dropped by it.
  4. Badge as a button that opens “Why incomplete”. Recommendation: yes.
  5. Inferred (LLM) is only reserved: no data field yet; the build spec names the provisional field provenance.kind = 'llm'.
