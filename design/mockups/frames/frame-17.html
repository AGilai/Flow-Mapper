Frame 17. Steps carry their own title, API and description (new)

Maintainer: "a step (main) shall include its title, its api, its description as 3 text sections in the step … a diagram option allowing to show more or less details per step with checkboxes title/api/description." Then, on review: "I was thinking that those 3 will appear on the step x of y — today it shows only the route — so the 3 can appear there; the diagram becomes less detailed; when moving between steps it shows the data we are discussing. An option to show what the mock shows also shall be configurable. Updating the step from the step or the upper bar — both." Defaults: the step bar shows all three for the current step (17g); arrows show the API only (today's density). Optional: the "Step details" toolbar menu puts Title / API / Description on every arrow (17b to 17f, kept as the opt-in). Edit: from the step or from the bar's "Edit step", one popover.

17a. Before and after, same four steps

Left: today, a step bar plus a "Step description" section (about 64 px) above a one-line-per-step diagram, and the text of the selected step is far from the arrow. Right (new default): one bar that carries the selected step's Title, API + route and Description (67 to 84 px for the three), above the same lean diagram as today: API only on each arrow. The separate section goes away; the on-arrow details are an optional toggle (17b to 17f).

17g. The step bar carries the step (default): Title, API + route, Description

The step bar ("‹ Step 3 of 6 ›") now shows the current step's details, so the diagram can stay lean (API only on arrows, today's 41 px rows) and stepping with ‹ › swaps the text in the bar. Block: Title (bold), API + route (mono, route muted), Description (human, else AI with the small AI tag). Description is up to 2 lines, then "… more", which expands inline (and "less" folds it back). Empty parts collapse: no title, the API is the first line; no description, a muted "Add a description" link opens the editor. "Edit step" stays at the right. Height (bar incl. 7 px padding top and bottom): title + API + 1-line description 67 px; with a 2-line description 84 px; API only plus the link 49 px. Today the bar and the "Step description" section together are about 102 px, so the new bar is shorter even in the worst case.

Rules and open questions

  • Defaults. The step bar shows Title, API + route and Description of the current step; arrows show the API only (today's 41 px rows). Stepping with ‹ › or clicking another arrow updates the bar. Nothing else sits above the diagram: the "Step description" section goes. The bar grows by at most about 36 px for a 2-line description (17g).
  • Step details panel (optional). Toolbar panel next to Squeeze with two sections, each with Title / API / Description checkboxes: "Step bar" (default all three) and "Arrows" (default API only; 17b to 17f draw arrows with all three). URL: sb= for the bar and sd= for the arrows, letters t, a, d, each omitted at its default (sb=tad, sd=a); an empty bar is sb= with no letters, kept in the URL. The bar may be emptied down to the stepper (and Edit step); arrows keep at least one, and unchecking the last one is refused (a step with none of the enabled arrow fields still falls back to its API). Button label: "Step details: bar 3 · arrows API". "Reset to defaults" at the panel bottom clears both. Per viewer in browser storage and the URL; Maximize (Frame 16) keeps the choice.
  • Bar block. Shows the lines chosen under "Step bar" (default all three). Title bold, API + route mono, Description human else AI (small "AI" tag), first paragraph only. Description is cut at 2 lines with "… more"; "more" expands inline, "less" folds. Empty parts collapse: no title, the API is the first line; no description, a muted "Add a description" link opens the editor. At 760 px the bar wraps: stepper and "Edit step" first, then the three lines full width.
  • Both edit entries. From the step: pencil on hover or selection (always visible on touch), right-click "Edit step description…", double-click on the arrow label, key E. From the bar: "Edit step" and the "Add a description" link. One popover; from the bar it is anchored under the bar (pointer on "Edit step"), from the step under the step. Esc or Cancel closes; unsaved text asks first. Saving updates the bar and the arrows together.
  • Step title: decided, edit-only for now. There is no manifest field. The title is stored with the step description record (new optional title, max 80 characters), edited only in the popover; harvesters cannot send it yet. The manifest schema and samples stay unchanged in this phase. Without a title the API is the first line everywhere.
  • Decided: Inside-the-service view. "Step details" also applies to the Inside-the-service view (same toggle, same bar). Rows there follow the same line heights.
  • Decided: Mermaid export. The title, when set, becomes the message text; the API goes in a note on that message. Without a title the message text is the API, as today.
  • Risk: layout. Arrow row height depends on the toggle, so the diagram height and the "squeeze" computation must take it from the row model (flow-draw-rows/layout), not from a constant. The bar height varies with the text (expanded "more"), so scroll-into-view of the selected step reads the real bar height.
  • Open: (1) With the bar carrying the text, is "Edit step" on the bar enough, or should the bar block itself be double-clickable to edit? Proposed: yes, double-click opens the popover. (2) A 2-line description plus title and API is 4 text lines at most, not 3: if 3 is a hard limit the description drops to 1 line and "more" does the rest. (3) The per-flow "Description" in the header is unchanged. (4) The "AI draft available" strip for updated descriptions (the earlier banner reading) is not drawn; say if wanted.
