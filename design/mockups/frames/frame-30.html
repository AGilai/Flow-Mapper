Frame 30. Store panel: one collapsible card per collection (CR #136)

The Info panel of a data-store node in a flow trace ("p81 (9 collections)": this flow touches 9 collections, in 21 of 59 steps). Owner's ask: the 9-collection fold is good, but inside it everything is one long list with the schema at the bottom. Everything below is clickable: cards, tabs, step chips, schema nodes. Data is invented.

  1. Collapsed by default. One 38px row per collection: chevron, name, "N calls", and R / W markers (lit = this flow does it, dashed = it does not). Nine collections fit in one screen. Only one card is open at a time (opening another closes the first), so the pinned header is never ambiguous. The store summary stays on top.
  2. Pinned header. An open card's header (name, store, call count, R/W, and the Calls / Schema tabs) is position: sticky; top: 0 in the panel's own scroll. Scroll the content and the header stays; the tabs stay too, so switching Calls / Schema never needs a scroll back up. The card has no overflow: hidden (that would break sticky); the radius is on the header itself.
  3. Calls tab (default). One row per operation in the code's own spelling (findById, find, updateOne...), with a read / write / delete mark, the fields it uses, the code location and step chips. A chip is a link: it jumps to that step in the trace and turns solid like today's. Sorted: writes first, then by first step.
  4. Schema tab. A field tree, not a DDL dump: name (bold mono), type (colour by kind: object, array, reference), required star, a note ("unique", "default false", "index"). Nested objects are indented under a rail and collapse; arrays are marked [] with the element type; the first level of nesting is open, deeper levels are shut. Fields this flow actually reads or writes get a dot and a faint tint, so the schema answers "which of these does the flow touch". Expand / collapse all in its header. The store page keeps indexes and the other consumers (as today).
  5. Redis (30d). Same card pattern for a key template. Tabs are Calls and Key: template with placeholders in accent, type, TTL (and where it is set), db, "also spelled" variants, and the registry line (as today's sp-reg). No schema tab: a Redis key has no field tree.
  6. Build notes. Reuses the cards from core/store-panel.js (title, ops, steps, links, fields); the tree needs the parsed field list (name, type, nested, array, required) from the schema source api.store already returns, loaded on the first click of the tab as today. Open card and tab are not kept in the URL. Not drawn: schema loading and error states, a collection with no schema ("No schema for X yet." as today), phone width.
