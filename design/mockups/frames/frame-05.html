Frame 5. New and changed down to a field

Left: the endpoint panel's message for sns:user-events event UserUpdated, a prod message the design changes. Right: the schema of the collection mongodb:users-db/users. Both are compared with the baseline (prod, Oct 21 14:02).

  1. The same three marks at field level: spark for a new field, ring for a changed one (with "was …"), struck-through muted row for a removed one. A coloured left edge on the row repeats the mark, so a long schema can be scanned.
  2. Children of a new field aren't marked again (devices[].certFingerprint is new because devices is).
  3. "Compared with" defaults to the baseline. Switching to "prod now" shows what changed in prod since the copy, using the same marks. That's how you spot drift before you apply a design.
  4. The head sentence counts the marks, and a component, endpoint or message that has any marked field below it shows "Changed" one level up.
