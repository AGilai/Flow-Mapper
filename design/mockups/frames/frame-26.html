page content scrolls under the header

Starts when a user presents two client certificates at the edge. The gateway validates both, resolves the account, and issues a session.

It covers both certificates, in order:

  • Device certificate: checked against the fleet CA
  • User certificate: checked against the corp-idp CA
  • Revocation lookup for each, cached for 5 minutes

Failures return 401 and never reveal which certificate was rejected.

Why two? The device certificate proves the machine is managed; the user certificate proves who is sitting at it. Either alone is not enough for the SASE policy, so the gateway refuses a login that has only one of them, even when that one is valid.

Timing. The whole exchange has a budget of 800 ms at the edge. The revocation lookups run in parallel and are the usual reason a login is slow.

  • A cold cache adds two OCSP round trips
  • A warm cache adds none

Related reading. See the certificate rotation runbook before changing either CA, and the session flow for what happens after a successful login.

Owner: identity team. Last reviewed with the gateway 4.2 release.

Decisions

  1. Region header is the toggle. One full-width button (chevron, “About this flow”, preview, count). Open, the controls share its row; nothing else is between toggle and content.
  2. Controls open only. Show all/Show less, A−/A+, Edit (button), ⋯. Collapsed shows none, so the row stays calm.
  3. Clamp ~4 lines, clean cut. No fade. Show all is not remembered per flow; it always starts clamped.
  4. Sticky header while expanded, so Show less is always reachable.
  5. Generate lives only in ⋯, with a cost note and a confirm. Empty state is one line.
  6. State. flow-mapper.flowinfo (open/closed, one global value) and the shared flow-mapper.textSize. Nothing else is stored.
  7. No description and no relations: the region is drawn collapsed, “No description yet”.
  8. Mockup-only choice: the ⋯ menu also holds “Copy description as Markdown” as a plausible second item; drop it if not wanted.
