What it does: signs a user in when the device presents two certificates, a device certificate and a user certificate, in one TLS handshake.

  • The agent sends both certificates to POST /v2/login
  • The server validates each chain against the tenant trust store
  • A revoked certificate (OCSP, cached 5 min) fails the whole login
  • On success the session is bound to the device fingerprint

Decisions

  1. Banner, not popover. The expanded Info is an inline banner that pushes the diagram down only while it is open, and only by what it holds. A popover would cover the diagram’s first rows, cannot hold a growing list of relations without its own scroll, steals focus, and is hard to use on a phone. The banner is the same thing a reader already sees today, so nothing gets hidden twice. The control is a labelled pill (icon, “Info”, “· 2 related”), so it reads as a button and the count says what is inside.
  2. Collapsed by default, with the first-visit exception. The first time a person opens a flow with a description the banner is open once; after that their choice rules. Without that, the bug’s “a new user does not find it” comes back. The count is always visible. With no description and no relations the control is not drawn; with only one of them it reads “Info” or “Info · 2 related” accordingly.
  3. Remembered per user in localStorage, the same for every flow, as the current boxes do: flow-mapper.flowinfo (open or closed, default closed after the first visit), flow-mapper.stepText (text hidden or shown), flow-mapper.stepFont (0 to 4 steps, default 1 = 13 px, A− and A+ stop at the ends and disable). The page works when storage is blocked.
  4. One column at every width: description, then related flows (maintainer’s choice).
  5. Description clamps at about four lines with “Show all”. Related flows are one line each: phrase, link, note cut with an ellipsis, and a chevron that opens that one row. Several rows may be open. More than six relations keep today’s “Show N more” and type chips.
  6. Markdown-lite in the flow and step descriptions (bold, italic, bullets, line breaks, links), the same renderer as about. Relation notes stay plain text. Editing still opens the raw text, by clicking the text or Edit.
  7. Keyboard. The Info control is a button with aria-expanded and aria-controls; Enter and Space toggle. The banner is a region and focus stays on the button. Each relation chevron is a button with aria-expanded. A− and A+ are buttons with aria-labels (“Smaller text”, “Larger text”) in a labelled group; “Hide text” is a button with aria-expanded and aria-controls. The existing arrow keys for steps keep working, and A+ never swallows them.
  8. Step panel. Full width. Title and “Step N of M” share the top row, so the walk always stays. “Hide text” collapses the API line and description and leaves one row of about 44px. A narrow window moves the title to its own line under the buttons. The text size changes the description only.
  9. Resizable panel is phase 2. Full width and Hide text answer the complaint; a drag handle adds state (a height per user) for a small gain. Shown in 25f for the maintainer to say yes or no.
  10. No new colours or tokens. Everything uses the existing surface, line, accent and focus tokens, and works in the dark theme.
