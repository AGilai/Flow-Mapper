Frame 35. Query cards: the where clause per data-store call

Maintainer: "There are already cards per query. Each card can expand to show the query we're discussing. The schema of the entire table is less important, it stays at the bottom." Data is invented (service devices-svc, collection Device). Cards are live: click a header, or use ↑ ↓ Enter.

  1. Each call card gets a chevron and a one-line query summary (35a). Expanded, it shows the query (35b): one readable call line, then labelled groups Filter, Projection, Update, Sort. Today's number, label, key, "only when" and code link stay exactly where they are.
  2. Helper filters are visibly distinct. Filters a shared DB helper adds (flag: helper_implicit_filter; lib:file:line) get a helper badge, a faint hatched row and a muted field name; the tooltip carries the flag text. Fields not in the schema (inDdl: false) keep today's amber "not in schema" mark.
  3. "Value from" is optional (35b / 35c). Without data the column is absent and the group footer says once "Values not reported by the harvester". With value on the field, the column shows where the value comes from, a kind tag, and an optional code link. A param source links to its card under Path parameters.
  4. Pane order (35e): call cards (expandable), Path parameters, then "Schema · from code" at the bottom, with the fields the open call uses marked (F filter, P projection, U update, S sort). A toggle "Only this call's fields" is off by default.
  5. A single step (35d) uses the same query block instead of today's "Fields" chips, with no card around it.
