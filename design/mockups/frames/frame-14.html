Frame 14. Mermaid import and export (0.27.2)

Maintainer: "import and export to mermaid - allow to both on flows - for import try to match existing components or ask user to match or warn that it will create unknown components". Spec: docs/plans/mermaid.md. Drawn for the night build; the maintainer overrides with a bug.

  1. Export is one menu, two items, on the flow header: Copy Mermaid and Download .mmd. No dialog: the toast confirms.
  2. Import is a three-step dialog: Paste, Match, Preview. Each step is a Back away from the one before; the draft is touched only by the last button.
  3. Matching is shown, never silent. Every participant has a select and a chip saying how it was matched (exact, similar, normalized, in prod, actor). Anything that creates something is amber and counted in a bar above the table.

Where it lives, and what it never does

  • Export is a menu on the flow header (Flows page, every environment, prod and the static preview included): "Copy Mermaid", "Download .mmd". Toast "Mermaid copied"; the download is named after the flow. Same text as GET /api/envs/:env/flows/mermaid and MCP export_mermaid.
  • Import Mermaid is in the draft bar's Edit menu on the Flows page, and on the flow header while Edit is on. Design environments only: sealed environments have no Edit menu, so the item is absent there (the server also refuses with 409 ENV_SEALED).
  • Import always goes into a draft. It never edits the environment. If no draft is open, the dialog first asks to open or create one. Step 3's button names the draft, and nothing is applied until the draft is applied (Review changes, Discard and Undo import all work on it).
  • Matching table (step 2): one row per participant, pre-filled by the match order. Only exact, alias, normalized and similar rows pre-fill a component; a name found only in prod defaults to "＋ create new" and offers "Import from prod (one level)" in the select (same one-level rule as frame 10). Unmatched rows carry a warning icon and the bar above counts what will be created. Create-new components all go into one subsystem chosen once.
  • Re-import is idempotent: pasting the same text again finds the components, endpoints and calls it made, reuses them and adds nothing. Step 3 then shows "0 new" with the reused count.
  • MCP import_mermaid {env, draft, text, matches?, dryRun}: a dry run returns the proposed matches (the table's content) and the counts, so an agent can correct matches and send them back; without dryRun it appends the same edits to the draft.
  • Small screens (760 px): the dialog fills the width; each table row becomes a stacked card: participant and chip on top, the select full width below, the hint under it.
