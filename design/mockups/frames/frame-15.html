Frame 15. Action items under each flow (new)

Maintainer: "an action-item segment, a table with number / owner / description / status", and "when no action items - no section - so need a button to create the section creating the first item". The lead decided it is a section of its own, linked to comments, not a comment type.

  1. No items, no section. The "Action items" section exists only while the flow has at least one item. The Comments header carries a small "+ Action item" button, and every comment gets "Make action item" next to Reply.
  2. The section sits above Comments in the bottom pane (.flow-bottom, max 40vh, scrolls), collapsible like Comments with the open state remembered per viewer. Header: "Action items (3 open · 5)", "+ Add" on the right.
  3. A table: #, Owner, Description, Due, Status. Open and in-progress rows are listed; done and dropped rows fold under "Show 2 closed" (open by default only while editing one of them).
  4. Editing is inline, in the row. Enter saves, Esc cancels. Cancelling the very first item removes the section again.
  5. Link to comments goes both ways: a row made from a comment shows "from Dana's comment" (scrolls to it and outlines it); the comment's thread shows one-line events ("Asaf G. created action #4 from this comment", "Dana closed #2").

Rules and what follows

  • Owner is free text for now, the same naive identity as comments (the name remembered on this browser; suggestions are recent names). When accounts arrive it becomes an account picker and existing names are matched.
  • Numbers are per flow and never reused. Deleting #4 leaves a gap; the next item is #5. The number is what people say in a meeting.
  • Statuses: open (outlined dot, --ink-2), in progress (half dot, --accent), done (--ok), dropped (grey, struck through). Open and in progress count as "open" in headers and badges. An overdue due date uses --warn and says "overdue"; only open and in-progress items can be overdue.
  • The flow list shows a small badge with the count of open actions on a flow (hidden at 0).
  • MCP: list_action_items {env, service, ingress}, add_action_item {…, owner, description, status?, due?, step?, commentId?}, update_action_item {id, …}. An item added by an agent is marked "by AI", as comments are.
  • Later: an environment-wide "All action items" page with filters by owner, status and subsystem, alongside frame 8 (all discussions).
  • Full copy carries action items (with their comment links); Blank and Components copies do not.
